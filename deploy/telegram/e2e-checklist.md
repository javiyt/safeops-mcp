## Checks

- [ ] `/start` from the administrator returns the SafeOps welcome message.
- [ ] Host status request returns a concise summary from SafeOps tools.
- [ ] Configured service status request works for a fictitious alias such as `service-alpha`.
- [ ] Configured container status request works for a fictitious alias such as `container-alpha`.
- [ ] Service logs are bounded, redacted, and treated as untrusted content.
- [ ] Container logs are bounded, redacted, and treated as untrusted content.
- [ ] Service restart request returns `approval_id=<id>` and `confirmation_code=<code>`.
- [ ] Correct confirmation code executes the approved action.
- [ ] Wrong confirmation code is rejected.
- [ ] Expired confirmation code is rejected.
- [ ] Canceling a pending action works and later confirmation fails.
- [ ] Unknown alias is rejected without inventing a fallback.
- [ ] Non-allowed Telegram user is rejected before OpenClaw is called.
- [ ] Group or channel message is ignored before OpenClaw is called.
- [ ] Request for shell, filesystem, direct Podman, or direct systemd access is refused.
- [ ] Confirm button executes only the approval shown in the message.
- [ ] Cancel button cancels only the approval shown in the message.
- [ ] Replaying a button after execution or cancellation fails.
- [ ] Oversized incoming message is rejected.
- [ ] Long outgoing response is split without exposing secrets.
- [ ] `safeopsctl audit list` shows `safeops-telegram` channel events with `telegram:<id>`.
- [ ] Mutable SafeOps audit rows use the configured `telegram:<admin_id>` identity.

## Final Audit

- [ ] No Telegram token appears in repository files.
- [ ] No Telegram token appears in OpenClaw logs.
- [ ] No Telegram token appears in SafeOps logs.
- [ ] Only configured Telegram user IDs can interact.
- [ ] Confirmation codes are generated by SafeOps and stored only as hashes.
- [ ] Button callback data uses closed verbs and approval IDs.
- [ ] Button replay cannot re-execute an approval.
- [ ] User sessions do not cross between Telegram users.
- [ ] Rate limiting works for repeated messages and callbacks.
